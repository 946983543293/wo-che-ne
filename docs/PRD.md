## 原始需求复述

清华大学校园面积大、停车点车极多，用户经常下课后/饭后忘记自行车停放位置，找车耗时。做一款**极简**手机 APP：停车时几秒内记下一笔「位置 + 照片」记录，找车时打开 APP 即可在地图上看到自己与车的位置并查看照片。产出可安装 Android APK，未来出 iOS 版，GitHub 开源。

---

## 1. 产品目标与核心指标

### 产品目标（3 个，互相正交）

1. **快**：停车记录全流程快到"不嫌麻烦"，用户赶时间也愿意用。
2. **准**：记录与找回的定位足够准，在校园建筑边缘、树荫下也能把用户引导到 10 米范围内。
3. **美**：极简不等于简陋，界面干净、有校园气质，用起来心情愉悦。

### 核心指标（北极星 + 护栏指标）

| 指标 | 目标值 | 说明 |
|---|---|---|
| 一次停车记录总时长（打开 APP → 记录完成） | **≤ 10 秒**（含拍 1 张照片） | 北极星指标；不拍照的极速路径 ≤ 5 秒 |
| 停车记录操作点击次数 | **≤ 3 次**（自动定位不算点击） | 打开即停车页 → 拍照（可选）→ 完成 |
| 找车路径时长（打开 APP → 看到地图+车位置） | **≤ 3 秒 / ≤ 2 次点击** | 首页「最近一次记录」一键直达 |
| 定位精度 | 开阔区 ≤ 5 m；建筑边缘 ≤ 20 m | 依赖高德融合定位 |
| 新手引导 3 步全部触达率 | ≥ 80% 新用户走完 3 步叠加引导 | 叠加引导随首次真实操作逐步出现，任一步可永久关闭 |
| 历史记录存储 | 默认 10 条，可设 3–20 条 | 达上限自动淘汰最早记录 |
| 隐私 | 照片 0 张进入系统相册，0 字节数据出设备 | 纯本地、无埋点、无统计 SDK |

## 2. 用户故事

1. As a 赶时间上课的学生，I want 停好车后 5 秒内记下位置（可以不拍照），so that 我不会因为操作麻烦而懒得记。
2. As a 吃完午饭忘记车停哪的学生，I want 打开 APP 一键看到车在地图上的位置和我的位置，so that 我能直接走过去而不是凭记忆瞎找。
3. As a 在相似停车点容易混淆的用户，I want 记录时拍 1–3 张照片（车位、标志物），找车时翻看，so that 我能从一排一样的车里认出我的车位。
4. As a 注重隐私的用户，I want 照片只存在 APP 私有目录、不进系统相册，so that 我的相册不被停车照片污染。
5. As a 第一次使用的新用户，I want 在真实界面里边做边学的叠加式引导（可勾选「以后不再提示」），so that 我不用看说明书就会用，之后永远不被打扰。

## 4. 核心页面流程与交互细节

### 4.0 全局导航

底部不设 Tab 栏（功能太少，Tab 是浪费）。首页承载「停车态 / 找车态」双状态；右上「历史」图标、左上「设置」图标。全部页面 ≤ 5 个；新手引导是叠加在真实页面上的半透明层（见 4.6），不占页面数。

### 4.1 首页（停车态 —— 无未使用记录时的默认态）

| 关键元素 | 说明 |
|---|---|
| 顶部 | APP 名「我车呢」+ 设置图标（左上）、历史图标（右上） |
| 中央大字 | 「车停好了？」+ 实时定位状态（定位中… / 已定位：清华·紫荆园附近，精度 6 m） |
| 主按钮 | 超大主按钮 **「记下车位」**（约占屏宽 80%） |
| 新手引导 | 仅首次：进入首页即触发叠加引导第 1 步（见 4.6） |

**操作路径**：打开 APP →（自动定位，无需操作）→ 点「记下车位」→ 进入拍照页。
**点击数**：1 次即可进入记录流程；拍照页再 1–2 次点击完成（见 4.2）。

### 4.2 拍照页（记录流程第二步，可跳过）

| 关键元素 | 说明 |
|---|---|
| 相机取景框 | 占屏幕约 70%，上方常驻提示条：「拍一张车的位置、周围标志物，找车不迷路」（拍第 1 张后提示消失，不打扰） |
| 已拍缩略图 | 底部横排，最多 3 格；点缩略图上的 × 可删除重拍 |
| 快门按钮 | 底部中央，标准圆形快门 |
| **「拍够了就这样」按钮** | 快门右侧，与快门同排、视觉权重次于快门（描边按钮）。文案固定为「拍够了就这样」；已拍 0 张时显示「不拍了，直接记」。点击后立即保存记录（位置 + 已拍照片 + 时间），返回首页并切换到找车态 |
| 拍满 3 张 | 自动保存并返回，无需再点 |

**交互定义**：用户随时可以结束——0 张、1 张、2 张、3 张都是合法记录。**不存在"必须拍满"的拦截**。
**完整路径点击数**：打开 APP（0）→ 记下车位（1）→ 快门 ×1（2）→ 拍够了就这样（3）= **3 次点击完成**；不拍照 = 2 次；拍满 3 张自动保存 = 4 次但无需点完成键。

### 4.3 首页（找车态 —— 存在最近一条记录且未归档时）

| 关键元素 | 说明 |
|---|---|
| 顶部大卡 | **「最近一次记录」**按钮卡：显示记录时间（如「今天 12:24」）、地点名、首张照片缩略图，整卡可点 |
| 次操作 | 「再记一笔」（切换到停车态流程）——用于同一天多次停车 |
| 历史入口 | 右上角不变 |

**操作路径**：打开 APP → 点「最近一次记录」→ 地图找车页。**2 次点击、目标 ≤ 3 秒**。

### 4.4 地图找车页

| 关键元素 | 说明 |
|---|---|
| 地图区 | 高德地图全屏，两个标记：蓝色「我」（实时定位蓝点+方向锥）、橙色「我的车」图钉 |
| 信息条 | 顶部浮层（P1-1）：**「车在东北方向 · 230 米」** + 记录时间/地点名 |
| 照片条 | 底部横排该记录的 1–3 张照片缩略图，点开全屏滑动浏览（双指放大） |
| 结束操作 | 找到车后点「找到了，归档」→ 该记录转为历史，首页回到停车态 |

### 4.5 历史记录页

- 列表按时间倒序：每行 = 首图缩略图 + 时间 + 地点名 + 距离当前位置的直线距离。
- 点行进详情（同 4.4 的布局，只读 + 可删除）。
- 数量受设置上限约束，淘汰时静默删除（含照片文件）。

### 4.6 新手引导（叠加式 Coach Marks）

引导**不是独立页面**，而是叠加在真实 APP 界面上的半透明遮罩层：界面整体压暗，目标控件被高亮圈出（挖空亮区），辅以箭头 + 气泡文字。用户在真实界面里**边做边学**，3 步与首次操作流程严格同步。

| 步骤 | 触发时机 | 高亮目标 | 气泡文案 |
|---|---|---|---|
| 第 1 步 | 首次启动进入首页（停车态） | 「记下车位」主按钮 | 「点这里，位置自动记」 |
| 第 2 步 | 首次进入拍照页 | 快门 + 「拍够了就这样」按钮 | 「顺手拍张照，找车不迷路；点这里随时完成」 |
| 第 3 步 | 首次完成记录回到首页（找车态） | 「最近一次记录」卡片上方浮现 | 「下次找车，点这里」 |

**交互规则**：
- 每步气泡上有「知道了」按钮，点击后该步消失；高亮目标本身也可正常点按（如直接点「记下车位」，既完成引导第 1 步、又真的开始记录，不强制先点「知道了」）。
- 每步气泡附带复选框「以后不再提示」（默认不勾选）；任一步勾选即永久关闭全部引导步骤。
- 遮罩区域点击不穿透，避免误触；任一步都可通过勾选框退出，**不设强制看完**。
- 引导完成/关闭状态写入本地偏好；设置页保留「重新查看新手引导」入口，重置后按同样 3 步随真实操作流再次出现。

### 4.7 设置页

| 设置项 | 取值 / 默认 |
|---|---|
| 历史记录保存条数 | 3–20，默认 10（步进器） |
| 重新查看新手引导 | 按钮 |
| 深色模式 | 跟随系统 / 浅色 / 深色（P1-3） |
| 震动反馈 | 开 / 关，默认开（Q2 已决） |
| 权限管理说明 | 跳系统设置（定位/相机） |
| 隐私政策 | 本地静态页（开源仓库内同步维护） |
| 关于 | 版本号、开源协议、GitHub 仓库地址 |

## 5. UI 设计稿描述（文字版 Wireframe）

### 美学方向推荐：**清新校园风（浅色为主）+ 自动深色模式**

**推荐理由**：① 用户是大学生，使用场景是白天户外停车点，浅色在阳光下可读性更好；② 「找车」是略带烦躁的场景，清新的薄荷绿/天青色系有情绪安抚作用，深色极简风偏冷峻，不符合「校园、轻快」的产品气质；③ 高德地图默认浅色底图，浅色系 UI 与地图融合度高，深色 UI 配浅色地图会割裂（夜间则整套切深色，含地图暗色样式）。

### 设计质量要求（v1.2 新增）

**设计质量红线（拒绝"AI 味"）**：
- UI 实现必须达到真实产品的质感，**禁止**千篇一律的渐变卡片堆砌、生硬的默认组件感。
- 严格遵循 §5 设计令牌的统一气质：清新校园风、大留白、一屏一个主行动点。
- 细节必须精致：圆角统一成体系（12–20 dp）、阴影极轻且有层次、字号层级分明（标题 24–28 sp / 正文 15 sp / 辅助 12–13 sp）、转场与按钮反馈有克制的小动效（150–250 ms 缓动）。
- 开发团队应主动引入 UI 设计类技能/规范进行设计走查把关，走查不通过不得进入交付。

**素材自产策略**：
- 图标、空状态插图、引导气泡配图、关于页插图等设计素材缺失时，由开发团队使用 AI 生图工具（火山方舟 Seedream）**自行生成**，不引入第三方版权素材。
- 生成风格必须贴合薄荷青绿（`#2BB673`）主色的清新校园风：扁平线条、浅色底、主色点缀。
- 叠加式新手引导的气泡保持轻量、无需大图；首页空状态、关于页等位置可使用生成插图。

### 设计令牌（Design Tokens）

| 项 | 值 |
|---|---|
| 主色 | 薄荷青绿 `#2BB673`（按钮、车标记） |
| 强调色 | 暖橙 `#FF8A3D`（「我的车」图钉、关键提醒） |
| 背景 | 米白 `#FAFAF7`；卡片纯白 + 12 dp 圆角 + 极浅投影 |
| 文字 | 主 `#1F2D2B`，次 `#6B7B78` |
| 字体气质 | 系统中黑体（Android: HarmonyOS Sans/MiSans 回退），标题 24–28 sp 粗体，正文 15 sp；大数字（距离）用等宽数字 |
| 圆角/留白 | 大圆角 16–20 dp，大留白，一屏一个主行动点 |
| 深色模式 | 背景 `#121A18`，主色不变，卡片 `#1E2926` |

### 各页布局要点

- **首页（停车态）**：上 1/4 为标题区；中央为定位状态 + 主按钮「记下车位」（高 64 dp，主色填充，白色粗体字）；底部留白，无冗余信息。整屏只有 1 个可聚焦的行动。
- **拍照页**：沉浸式取景；顶部提示条半透明黑底白字；底部控制条 = 缩略图（左）、快门（中）、「拍够了就这样」（右，描边样式）。拍满 3 张自动收工。
- **地图找车页**：地图全屏出血；顶部胶囊浮层显示方向+距离（大字等宽数字）；底部照片条悬浮于地图之上，半透明白底。
- **历史记录页**：标准列表卡，左图右文，卡片间距 12 dp。
- **新手引导叠加层**：界面压暗为 60% 黑，高亮圈用主色描边 + 圆角挖空；气泡白底圆角 12 dp、带主色小箭头指向目标；气泡内一行文字 +「知道了」按钮 +「以后不再提示」复选框，全部单手可达。

## 6. 开源专题（必读）

### 6.1 三种常见开源协议，大白话版

| 协议 | 一句话解释 | 别人能拿你的代码干嘛 | 用了闭源 SDK（如高德）行不行 | 适合本项目吗 |
|---|---|---|---|---|
| **MIT** | 「随便用，出了事别找我」 | 可商用、可闭源、可改名再发布，只需保留你的版权申明 | ✅ 兼容，MIT 不强求衍生作品开源 | ⭐ **推荐** |
| **Apache-2.0** | 「随便用，还送你专利授权，但改了要说明」 | 同 MIT，但多了明确的专利授权条款，且修改文件需标注 | ✅ 兼容 | 可选（比 MIT 略正式，个人小项目用 MIT 足够） |
| **GPL-3.0** | 「用我的可以，但你的整个作品也必须开源 GPL」 | 传染性最强：基于 GPL 代码发布的软件必须同样开源 | ⚠️ 有争议：与闭源 SDK 静态链接/捆绑分发可能产生冲突，社区普遍建议避免 | ❌ 不推荐 |

**结论：推荐 MIT License**。理由：个人开源项目最常见、最简单、对使用者最友好，且与闭源的高德地图 SDK 无冲突；GitHub 新建仓库时选 License 模板一键生成即可。注意：MIT 只约束**你的代码**，高德 SDK 本身受其商业条款约束，需在 README 注明「需自行申请高德 Key」。

### 6.2 开源红线（四条铁律）

1. **高德 API Key 绝不进 Git 仓库**：Key 放在 `android/local.properties`（Android）与环境变量中，代码里用占位符读取；`.gitignore` 必须包含 `local.properties`、`.env`、`*.key`、`*.jks`（签名文件！）。一旦泄露进 Git 历史，删文件没用，要重写历史或吊销 Key 重申请。
2. **开源也需要隐私政策**：即使纯本地、零数据收集，也要在仓库放一份 `PRIVACY.md`，写明「本应用不收集、不上传任何用户数据，所有数据仅存储于用户设备」，应用内设置页可查看。应用商店分发和合规检查都会要。
3. **地图类 SDK 合规要求（工信部）**：**用户同意隐私政策前，不得初始化高德 SDK**（也不能提前读写设备信息）。实现方式：首次启动先弹隐私政策同意框 → 用户同意后再调用高德初始化；不同意则不能使用定位/地图功能（可仅保留查看历史记录的降级能力）。这一条是 App 合规检测的高频挂科点，务必在架构设计时就留好「延迟初始化」的口子。
4. **素材版权（v1.2 新增）**：图标、插图等设计素材由 AI 生图工具（Seedream）自行生成，可随项目一同开源，无第三方版权风险；建议在仓库保留生成提示词记录（如 `assets/prompts.md`），方便复现、迭代与社区二次创作。

## 7. 技术风险与对策

| 风险 | 场景 | 对策 |
|---|---|---|
| GPS 信号弱 | 教学楼/宿舍楼背阴面、树荫、半地下车棚，定位漂移几十米 | ① 用高德**融合定位**（GPS+Wi-Fi+基站）而非纯 GPS；② 定位精度 > 20 m 时 UI 明示「当前定位不准，主要靠照片认车」，弱化地图权重；③ 允许记录后手动微调图钉（P2 可考虑，本期先靠照片兜底）；④ 照片提示语引导拍「周围标志物」，让照片成为弱信号下的主要找回手段 |
| Flutter 相机连拍性能 | 中低端机连拍 3 张卡顿、预览掉帧 | ① 用 `camera` 官方插件 + `ResolutionPreset.medium`（照片只是认车用，无需高分辨率）；② 拍完异步写盘、先出缩略图；③ 限制 3 张上限本身就是性能护栏 |
| Android 13+ 权限模型 | 定位（ACCESS_FINE_LOCATION）、相机、通知权限均为运行时申请 | ① **按需申请、给理由**：打开 APP 不弹权限；点「记下车位」才申请定位，进拍照页才申请相机，并先弹一页「为什么要这个权限」的说明；② 被拒绝时降级可用（定位被拒 → 允许纯照片记录 + 手动输入地点；相机被拒 → 允许纯定位记录）；③ 通知权限本期用不到就不申请 |
| 后台/杀进程后定位丢失 | 找车时冷启动重新定位慢 | 冷启动首页找车态即开始定位，地图页先显示「车的位置」（已存本地）+「我的位置」加载中骨架，定位完成再刷新蓝点 |
| 高德 Key 额度/审核 | 个人开发者 Key 有日调用量限制 | 纯本班个人使用量级远低于免费额度；README 指导使用者自行申请 Key |
| 隐私合规检测 | 工信部 SDK 检测 | 见 §6.2 第 3 条：延迟初始化 + 隐私政策前置 |
